## 수정037-1 재업로드 후 추가 반영

- 관심종목이 아닌 검색결과에서 알람을 설정·삭제할 때는 메모리만 변경하고 서버·localStorage·sessionStorage에 쓰지 않음. 관심종목 추가 절차에서 서버 저장을 진행하며, 관심종목이 아니면 로그아웃·새로고침·새 브라우저에서 복원하지 않음.
- 관심 여부는 5개 폴더 전체로 판단. 관심종목 알람 변경·삭제는 기존 서버 API에 반영.
- 임시 알람이 있는 종목을 관심종목에 추가할 때 알람 저장 후 관심목록 저장 순서로 처리. 알람 저장 실패 시 관심목록 추가를 진행하지 않고 임시값 보존. 관심목록 저장 실패 시에도 임시값과 기존 목록을 보존하고 재시도 가능. 이 경우 서버 알람값이 먼저 저장될 수 있으나 관심목록에 없는 값은 재로그인 시 복원하지 않음.
- 여러 폴더 중 일부에서 제외해도 다른 폴더에 남으면 영구 알람 유지. 마지막 폴더에서 제외하면 현재 화면에서만 임시 유지하고 재로그인 시 미복원.
- 마지막 관심 제거 시 서버 알람을 자동 삭제하지 않음. 문서에 없는 삭제 정책과 다른 기기의 데이터 유실을 피하기 위해 비관심 서버 값은 표시·복원에서 제외. 사용자가 임시 알람을 명시적으로 삭제한 뒤 다시 관심종목에 추가할 때는 그 삭제를 서버에 반영해 옛 알람이 되살아나지 않도록 처리.
- 관심종목의 서버 값을 다시 불러오면 이전 임시값이 최신 서버 값을 덮지 않도록 승격 완료·영구 저장 성공 후 세션 override 제거.
- 관심목록·알람 쓰기는 공통 잠금으로 순서 보장. 현재 API 두 요청의 여러 기기 간 원자성은 FE만으로 보장할 수 없으며, 완전한 원자성이 필요하면 BE 트랜잭션 지원 필요.
- **수정037-1 3쪽의 현대차 실제 20일선 추세와 `ma20_up` 값의 일치 여부는 BE 확인 필요.** FE는 `true`일 때만 U를 표시하며, 전체 종목의 실제 추세를 별도 계산하지 않음. 이는 아래 28번의 10일선 전환과 별도 확인 사항.

## 28번 BE 연동 요청

- `/jminfo`와 같은 전종목 일괄 응답에 **10일 이동평균 상승 추세 여부** 제공 필요.
- 상승 판정 기준(예: SMA10 전일 대비 상승인지, 연속 상승인지)과 응답 필드 이름 확정 필요. `ma10_up`은 제안이며 현재 API에 존재한다고 가정하지 않음.
- 현재 이슈 #9는 `ma20_up`을 U 표시 기준으로 명시하므로 FE에서 이 값을 임의로 10일선으로 재해석하지 않음.
- 종목별 캔들을 수천 번 조회하여 FE에서 전종목 추세를 별도로 계산하는 방식은 사용하지 않음. `/api/stocks/{ticker}`는 여러 차트 계열을 함께 조회하므로 그 경로를 전종목에 반복 호출하면 요청량이 더 증가함.

## 검증

- 프로덕션 빌드 및 타입 검사 통과.
- API 회귀 테스트 12개 통과.
- E2E 62개 통과: 수정037-1 임시·영구 알람 저장 정책 회귀 8개, 기존 알람색·주월봉·검색조건·계정 기능 포함.
- 실행 중인 개발 서버와 충돌하지 않도록 동일 소스를 별도 디렉터리에 복사해 프로덕션 빌드·E2E 실행. 앱·공개 자산·테스트 파일의 해시가 원본과 동일함을 확인.
- 2,556개 종목 입력 Event Timing 최대 보고값 40ms(50ms 미만) 유지.
- 브라우저 테스트는 모의 API로 검증하며 실제 계정의 운영 서버 데이터까지 검증한 결과는 아님.
- 원본 엑셀의 상태값은 변경하지 않음.
