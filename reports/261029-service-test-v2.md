## 별 색상

| 북마크 | 관심폴더 포함 | 표시 |
| --- | --- | --- |
| 없음 | 없음 | 속이 빈 검정 테두리 별 |
| 있음 | 없음 | 노랑 `#FFFF00` |
| 없음 | 있음 | 하늘색 `#00B0F0` |
| 있음 | 있음 | 빨강 `#FF0000` |

관심폴더 포함 여부는 현재 열린 폴더가 아닌 전체 5개 폴더를 기준으로 한다. 한 폴더에서 삭제해도 다른 폴더에 남아 있으면 관심종목 색상을 유지한다. 서버 저장이 실패하면 기존 개수·색상·알람을 유지한다. 폴더 한도는 `/api/watchlist-max` 응답을 사용하며 자료 이미지의 50개로 고정하지 않는다.

## API와 기존 동작

- 관심종목은 기존 `/api/watchlist`의 1~5번 슬롯으로 저장하며 로컬 목록을 서버 목록에 자동으로 합치지 않는다.
- 관심종목의 영구 알람과 일반 검색 종목의 세션 임시 알람 구분을 유지한다.
- 손절폭 요청 키 `filter_losscutmargin`과 값 `0 / 50 / 500100 / 1000150 / 1509999`를 유지한다. 경계값의 실제 계산은 기존 백엔드 계약을 따른다.
- `완`인 항목의 비고에 적힌 “현재 상태 유지”, “테스트를 잘못했음”, 데이터 수신 시점 차이 등은 새 결함으로 재해석하지 않았다.

## 검증

- 프로덕션 빌드 성공. 빌드에 포함된 TypeScript 검사 통과.
- `npm run test:api`: 12개 통과.
- 프로덕션 Chrome E2E: 최종 코드로 전체 104개 시나리오 통과. 제거된 상태 영역을 참조하던 기존 테스트는 새 알림 위치에 맞춰 갱신했다.
- 수정045~052 신규 시나리오: 별 색상 네 상태, 전체 폴더 기준 포함 여부, 행별 넣기/빼기 요청과 개수, 중복·없는 종목 무시, 용량 초과, 저장 실패와 재시도, 키보드 메뉴, 1440×1000·1100×720 화면 배치, 실제 캔버스의 빨간 알람선 복원·갱신·삭제·실패 시 유지·종목 전환을 확인했다.
- 2,556종목 입력 성능 회귀 테스트 통과. 최종 실행의 Event Timing 최대 보고값은 종목이름·종목코드·검색 제목 모두 40ms였다. 측정 환경의 결과이며 모든 기기 성능을 보장하는 수치는 아니다.
- 테스트한 임시 QA 디렉터리와 작업 디렉터리의 `app`, `public`, `tests` 파일 내용 일치를 확인했다. `git diff --check` 통과.

브라우저 테스트는 API 응답을 모킹해 FE의 표시·요청·복원·실패 처리를 검증하며 운영 서버의 실제 데이터 계산이나 저장 결과를 직접 검증한 것은 아니다.

## 백엔드 작업 필요 여부

이번 `미` 7개 항목은 기존 API로 FE에서 반영 가능하다. 추가 백엔드 API가 없어 남겨 둔 항목은 없다. API의 손절폭 경계 계산이나 운영 데이터 정확성은 FE가 변경하지 않는다.
